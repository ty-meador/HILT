Inspector JSON Contract¶

Floor Technicians reading a run should start at docs/floor-technician.md. This page is the consumer contract those fields live in.

The Inspector TUI is outside the Python port's current scope. Its input contract is not. Every completed node produces a RunResult, and RunResult.to_json() returns a plain Python object that json.dumps() accepts without an encoder. The root result is self-contained: consumers do not need the live TestComponent objects to reconstruct the run tree. CI that already speaks JUnit XML consumes a projection of the same tree (docs/junit-xml.md); that reporter is not a second evidence record.

Every full TestComponent.run() atomically writes the root RunResult.to_json() payload to result.json in the timestamped run directory beneath HILT_ARTIFACT_ROOT. The file is present for Pass, Fail, and Aborted outcomes. Its absolute path is published by the final entry in the root node's timeline, with artifact name result and artifact type run-result; consumers do not need to derive the run directory name.

Version 1 result¶

Field JSON type Meaning
format_version integer Schema version; currently 1.
state string One terminal state: Pass, Fail, or Aborted.
failure object or null JSON-safe framework failure, including nested causes.
timeout object or null Structured time-budget evidence when a deadline determined or contributed to this state.
test_case string Stable name of this node.
type string suite, test, parallel, or sequence: the node shape, in the vocabulary of build_suite.
ancestor_names array of strings Root-to-this path, inclusive.
bread_crumbs string Display path, exactly ancestor_names.join("/").
summary_tree object Recursive snapshot rooted at this node.
physical_location string PHYSICAL_LOCATION, or unknown when absent.
env object Environment snapshot taken at the start of the run, filtered per the run's allow or deny list; see below.
run_data object Detached structured evidence snapshot: the JSON-safe view of the node's ctx, plus, on a leaf, the evidence its verdict carried. It always contains a framework-owned measurements array: one entry per utils.measure call on this node, in call order, empty when the node measured nothing.
suite_target string or null The loader target that produced the run, as hilt run resolved it: an absolute suite file or module name, ::, and the suite class name. hilt inspect loads this suite for its Re-Run tab, so the technician re-runs a node with the code that ran in production; --suite overrides it. null when the run was started without one, from a developer's own harness. Added within version 1 on 2026-09-10; a consumer written before it treats the field as additive.

A measurement entry is {name, value, unit, limits, in_limits, timestamp} as docs/measurements.md defines it: value is a number, or null when the suite tried to take the reading and could not (issue #159; a hole in the series, never a zero), limits is {low, high} with null for an open side or null altogether, in_limits is true, false (always false for a null value against a window), or null when no window was given, and timestamp is UTC ending in Z. in_limits is evidence, never a verdict; version 1 defines no aggregation, SPC, or Cpk, and an integrator must not infer them from the entries. Because result.json is the root's record, the entries a leaf recorded reach the file through measurements on its summary_tree node, not through this run_data.

Python-only lifecycle details such as the internal slot and raw return value are not part of this payload. Consumers must treat unknown fields as additive and select a decoder by format_version (see Versioning policy).

The env snapshot is filtered by the run, not by the schema¶

Version 1 publishes the run environment as the run declared it. TestComponent.run() and TestUtils accept either env_allow or env_deny (both is a ValueError): a list of regular expressions matched with re.search against each variable's name. TOKEN therefore matches GITLAB_TOKEN; anchor as ^HOME$ for an exact name. With an allow list only matching names are published; with a deny list matching names are withheld. Values are never hashed or rewritten — a variable is either present verbatim or absent.

With neither list the snapshot is verbatim: every value present at run start, including tokens or credentials injected by CI or the shell, is serialized into the artifact. Keeping secrets out of an unfiltered run environment is the operator's obligation.

DEBUG override. When the source environment carries environment=DEBUG, the declared list is ignored and every variable is published. The run logs a warning — DEBUG mode detected, ignoring provided <allow|deny> list and including ALL environment variables — so the artifact's extra content is explained in its own timeline.

The filter is applied once, at the root, and every node and every RunResult sees the same filtered view. PHYSICAL_LOCATION and HILT_ARTIFACT_ROOT are read from that view, so an allow list must let them through to keep their effect. Decoders must not assume any particular variable is present (ruling on issue #53, 2026-09-03).

Version 1 timeline¶

Each run() creates a timestamped directory directly beneath HILT_ARTIFACT_ROOT. Point-in-time artifacts are stored at that run-directory root. Every executed node that owns a discrete log receives a child directory containing:

  • timeline.log — a streamed human view with one escaped line per entry;
  • timeline.jsonl — the authoritative Inspector record, with one complete JSON object per physical line.

Both files are flushed after each entry. Consumers may read the JSON Lines file while a run is active and retain every complete line after interruption. The child-directory name is framework-owned and must be treated as opaque; use TestComponent.log_path rather than reconstructing it.

Every version-1 timeline object contains these fields:

Field JSON type Meaning
format_version integer Timeline-record schema version; currently 1.
timestamp string Timezone-aware UTC timestamp ending in Z.
scope array of strings Root-to-emitting-node path, inclusive.
level string Lowercase Python logging level name.
message string Fully rendered log message. Newlines remain escaped within the JSON line.

An artifact-pointer entry additionally contains all four fields below. They are absent from ordinary records rather than set to null.

Field JSON type Meaning
artifact_name string Captured artifact name, or result for the root result.
artifact_path string Absolute path of the published artifact or root result.json.
artifact_type string Captured artifact type, or run-result for the root result.
artifact_timestamp string The evidence timestamp in UTC; for the root result, its publication time.

Authored suites, sequences, and parallel nodes own a log by default. Leaves roll their records into the nearest owning ancestor. A sequence, parallel node, or composed suite constructed with discrete_log_file=False also rolls up. Pending nodes create no files.

Two records, two version fields¶

A run therefore produces two versioned records, and each carries its own format_version:

Record Where it lives Version field
Result result.json at the run-directory root; the serialized root RunResult.to_json() and structural view rooted at summary_tree format_version on the result object
Timeline timeline.jsonl beneath the run directory; the temporal view format_version on every JSON Lines object

The two version numbers move independently. The summary tree links the structural view to the temporal view through each node's log_path (ruling on issue #106, 2026-09-04: the link is additive within result version 1). An Inspector selects a node in the tree, resolves log_path against the run directory, and reads that node's chronology.

Versioning policy¶

format_version is an integer on every record the framework emits: the result, every timeline line, and the envelope Artifact.to_json() writes for point-in-time evidence. One rule governs all of them.

  1. Additive within a version. Adding a field to a framework-owned object keeps the number. So does adding a key that the record already declares open (env, run_data, and the failure object). A consumer must accept fields it does not know and must not fail on them; it reads what it was written for and ignores the rest.
  2. Breaking bumps the version. Removing or renaming a field, changing a field's JSON type or nullability, changing the meaning of an existing value, adding a member to a closed set (state, type, declared, the failure state), moving or renaming result.json or timeline.jsonl, or changing the one-object-per-line rule bumps the number. A bump is a contract change and follows the workflow in STANDARDS.md section 7: it is raised as an issue and ruled on before its MR opens.
  3. Consumers declare what they accept. A decoder reads format_version before any other field, accepts the versions it was written for, and refuses every other version loudly, with an error that names the version found and the versions accepted. A best-effort read of an unknown version is a silent misreading and is not permitted. Within an accepted version the decoder validates against the published schema for that version.
  4. The records version independently. Bumping the result does not bump the timeline, and the reverse. The per-node log_path link is additive within result version 1 (ruling on issue #106, 2026-09-04).
  5. Every change amends the schema in the same MR. A field added within version 1 appears in the version-1 schema and in this document before the framework emits it. The self-tests close every framework-owned object against its schema, so an emitted field the schema does not name is a red gate, not a silent contract change. A bump publishes a new schema file and leaves the previous one in place: a run directory written under version 1 stays readable by a version-1 consumer for as long as the record exists.

Before 1.0.0 the record may change in place under version 1, because no consumer exists to break; the type vocabulary was renamed this way to match the composition vocabulary (ruling on issue #111, 2026-09-06), and measurements[].value became nullable this way for a reading not taken (ruling on issue #159, 2026-10-20). From 1.0.0 rule 2 applies as written.

Published schemas¶

Record Schema Draft
Result docs/schema/result-v1.schema.json JSON Schema 2020-12
Timeline docs/schema/timeline-v1.schema.json JSON Schema 2020-12
Artifact envelope docs/schema/artifact-v1.schema.json JSON Schema 2020-12

The published files are the consumer contract, and they are open: framework-owned objects do not forbid additional properties, so a consumer validating with the file shipped in one release accepts the additive fields of a later release within the same version. Three objects are open by design and stay open under the self-tests as well: the failure object (a TestFailure subclass may add fields), env (station-defined names), and run_data (suite evidence beyond the framework-owned measurements slot). The measurement object itself is open as well, so a field added to it within version 1 is accepted by a consumer validating with this file.

tests/test_inspector_schema.py validates every emitted result.json and every emitted timeline line against these files on each gate run, first as published and then with every framework-owned object closed. It also validates emitted point-in-time captures against the artifact-envelope schema with the envelope closed. That schema describes the existing Artifact.to_json() shape: format_version, name, type, timestamp, and data. The observation may be any JSON value, including explicit null. Additive envelope fields remain acceptable to consumers; the payload is never closed. The internal Inspector capture reader consumes this envelope under the same version policy. The root run-result pointer instead uses the result schema; it is not an envelope.

Summary tree node¶

Every summary_tree node contains exactly these version-1 fields:

Field JSON type Meaning
name string Stable node name.
type string The same node-type discriminator used by RunResult.
state string or null Terminal state, or null when a declared sequence step did not run.
failure object or null JSON-safe failure for this exact node.
timeout object or null Structured time-budget evidence for this exact node.
log_path string or null POSIX path of this node's timeline.jsonl, relative to the run directory. Null when the node never ran or when its records rolled up into an ancestor.
children array Ordered child nodes. Groups retain declaration order after settlement.
evidence object or null The readings this leaf's verdict carried: PASS({...}) or TestFailure(..., evidence={...}), validated entry by entry and detached. Null on a node that is not a leaf, that never ran, or whose verdict carried none.
evidence_declared array of string or null The keys the leaf's @evidence declaration promised on PASS, in declaration order. A declared key absent from evidence is a reading that was not taken; show it by name. Null when the node is not a leaf or declared nothing.
measurements array or null Every utils.measure call this node recorded, in call order, as measurement objects (docs/measurements.md). An array on every node that ran, empty when it measured nothing; null when the node never ran, matching state. A measurement does not satisfy an @evidence declaration and in_limits: false is not a Fail.

A null tree state means pending/unreached; it is not a fourth terminal state. A stopped sequence retains its unexecuted descendants with null states, so the root snapshot still describes the full declared tree.

log_path is relative so that a run directory copied to another machine keeps every link intact. Consumers resolve it against the run directory they opened, the same directory that holds the point-in-time artifacts. A node with a terminal state and a null log_path rolled its records into an ancestor; the nearest ancestor with a non-null log_path holds them, and the root always carries one. A node whose state is null never ran and has no chronology anywhere.

Failure shape¶

Failures use their framework to_json() methods. TestFailure and its subclasses retain the failure name, message, state, comparisons, and bug metadata. An ExternalIntegrationFailure retains its hook and JSON-safe cause. OperatorInterrupt retains operator: true and the signal name so a Ctrl-C is not mistaken for a hook failure. Arbitrary exception objects and live values degrade to descriptive JSON-safe forms rather than making serialization fail and masking the evidence.

Timeout shape¶

When no deadline contributed to a node's state, timeout is null. Otherwise it carries these fields:

Field JSON type Meaning
reason string Always timeout.
declared string The winning declaration: fail_after or abort_after.
budget_seconds number Positive finite duration declared on the winning clock.
elapsed_seconds number Active window time consumed when that clock fired.
clock string Root-to-declaring-node path of the winning clock.

For fail_after, failure also contains the hardware-facing TestFailure. For abort_after, failure may be null because the framework does not forge a verdict; the timeout record carries the reason for the node-local Aborted state.

Integrators should use ancestor_names as the durable node identity and bread_crumbs only for display. Names may contain /; the array is therefore the canonical representation.

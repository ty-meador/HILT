API Stability¶

1.0.0 is a promise. This document states what the promise covers, how version numbers carry it, how a name leaves the surface, and where every change is announced. The developer reads it to know which names are safe to build a station on and how much warning a change carries. Suites written for 1.0 keep running on every 1.x, so the Floor Technician's stations do not break on an upgrade.

The self-tests hold the framework to this document (tests/test_public_surface.py): the reference table below and hilt.__all__ must name the same set, every example and every documented code block imports only that set from the package root, and hilt.__version__ reports the installed distribution.

The public surface¶

hilt.__all__ is the public surface. Everything else is private.

  • A name is public if and only if it appears in hilt.__all__. Import it from hilt; the module a name is defined in is an implementation detail and may move without notice. from hilt import TestComponent is a promise; from hilt.base import TestComponent is not.
  • The documented attributes, methods, parameters, and raised exceptions of a public name are part of the promise. "Documented" means named in this document, in docs/contracts.md, docs/idioms.md, docs/inspector-json.md, docs/junit-xml.md, or docs/hilt-check.md, or in the name's own docstring.
  • A public object has no attribute of a private type. Every value a suite can read from a public object carries a public type, so the reader can follow every name back to its meaning. ScopedLogger is promised as its logging.LoggerAdapter base plus the documented scope and bread_crumbs additions.
  • hilt.__version__ is public: the installed distribution's version string.
  • The invariants in docs/contracts.md are promises in their own right. A change that weakens one is a breaking change even when no name moves.
  • The records the framework emits (result.json, timeline.jsonl, the point-in-time artifact envelope) are promised through their published JSON Schemas and format_version, under the policy in docs/inspector-json.md.
  • Three environment variables are public configuration, and the framework reads no others: HILT_ARTIFACT_ROOT, the artifact root when TestUtils is given none; environment=DEBUG, which publishes every variable despite an env_allow or env_deny list and logs a warning saying so (docs/inspector-json.md); and SSH_AUTH_SOCK, the SSH agent get_shell and use_shell fall back to when no credential is given. The run environment as a whole is published as evidence under env_allow / env_deny, not read as configuration.
  • The hilt run command line is public in two respects: its exit status contract (0 Pass, 1 Fail, 2 Aborted, 3 usage error) and its --json record, which is the result.json record under the same format_version policy (docs/hilt-run.md). The hilt.cli module behind it is not.
  • The hilt new command line is public in two respects: the files it writes (a gated-PASS suite and a matching self-test stub) and its exit status (0 wrote the files, 3 usage error). The hilt.scaffold module behind it is not (docs/hilt-new.md).
  • The hilt inspect command line is public in three respects: its selection rule (PATH is a run directory or its result.json; no PATH opens the most recently modified result.json under HILT_ARTIFACT_ROOT, default artifacts/), its exit status (0 the Inspector was closed, 3 nothing to inspect, not a saved version-1 run, or a --suite that cannot be loaded), and the rule that the Re-Run tab executes only the suite the run recorded as suite_target or the one --suite names, never one derived from evidence. The screen behind it, hilt.inspector_app, and the re-run adapter, hilt.inspector_rerun, are not (docs/inspector.md).
  • The hilt-check command line is public in two respects: its exit status contract and the rule codes it ships (docs/hilt-check.md). The Python API of the hilt_check package is not.

Private, with no promise attached:

  • Any name beginning with an underscore, at any depth.
  • Every submodule path. hilt.lifecycle, hilt.routing, hilt.executor, hilt.timeline, hilt.mock, and the rest are the framework's organs; the self-tests import from them, suites do not.
  • Annotation-only aliases that appear in signatures but are not exported (WaitPredicate, HaltReason, ExecFn). They are documented by their expansion.
  • Directory and file names beneath the artifact root. TestComponent.log_path and the result pointer in the timeline are the API; the layout that produces them is not.
  • The transports, RemoteInterface, SshInterface, and SerialInterface. A suite author never constructs a transport: TestUtils.use_shell and TestUtils.get_shell open an SSH connection and hand back a Shell; TestUtils.use_serial and TestUtils.get_serial do the same for a console by device path, and their documented parameters are the promise the serial transport is reached through. Transport authors and the self-tests import hilt.remote, hilt.ssh, and hilt.serial directly; a transport contract for third parties is a design note of its own (issues #91, #93–#97).
  • The Device API backends, DeviceApiInterface, HttpInterface, CoapInterface, and MockDeviceApi. A suite author never constructs one: TestUtils.get_http and TestUtils.get_coap open the session and hand back a DeviceApi. Self-tests import hilt.device_api directly.
  • hilt.junit.JunitXml. The runner owns the reporter: hilt run --junit PATH is the promised way to a JUnit report. A harness adapter that imports hilt.junit directly does so without the promise, as docs/junit-xml.md says.
  • The self-test fixtures, the loopback sshd, and MockTransport. A transport double for suite authors is a feature to be designed, not a side door into the test kit.

Version numbers¶

The distribution version follows Semantic Versioning 2.0.0: MAJOR.MINOR.PATCH.

Before 1.0.0 (0.y.z) nothing is promised. A name may be renamed or removed in any release, without a deprecation period; the composition vocabulary ruling on issue #110 (case and group removed outright, a hilt-check rule naming the replacement) is the precedent. Every such change still lands in CHANGELOG.md under the release that makes it, so the trail exists before the promise does.

From 1.0.0 a release bumps exactly one component:

Component Bumped when Examples
MAJOR A promise is broken. A name leaves __all__; a documented parameter, attribute, or return type changes incompatibly; a contract in docs/contracts.md weakens; a format_version bumps; requires-python rises; a hilt-check rule code is removed or renamed.
MINOR The surface grows or a deprecation is announced. A new name in __all__; a new optional keyword parameter; a new field on a record within its format_version; a new hilt-check rule; a name marked deprecated.
PATCH Behaviour is corrected without changing the surface. A bug fix that brings behaviour in line with a documented contract; a dependency bump that changes nothing a suite can observe; documentation.

Two consequences the developer can rely on:

  • A fix is not a break. When a documented contract and the code disagree, the document is the promise and the code is the bug. Correcting it is a PATCH even if a suite depended on the wrong behaviour.
  • A format_version bump is a MAJOR. The Inspector and the harness that read a station's records are part of the station. A new record version that an installed consumer refuses is a break, whatever the Python surface did.

Dependencies are private. asyncssh and anything else the framework imports may change major version in a MINOR or PATCH release as long as nothing a suite can observe changes; a dependency that becomes observable (a type in a public signature) becomes part of the promise at that moment and is documented as such.

Deprecation¶

A public name is never removed in the MAJOR line that introduced it. It is deprecated first, and removed no sooner than the next MAJOR release and no sooner than two MINOR releases after the deprecation was announced. Both conditions hold at once.

Announcing a deprecation is one MR that does all of the following:

  1. The old spelling keeps working, with the documented behaviour, for the whole deprecation period.
  2. Calling it emits DeprecationWarning through warnings.warn with stacklevel=2, so the warning points at the suite's line, not the framework's. The message names the replacement and the release that will remove the old spelling.
  3. The reference table marks it with Deprecated in x.y, removed in z.0 and the replacement, and the section that documents the name says the same.
  4. CHANGELOG.md records it under Deprecated for the release that announces it, and under Removed for the release that removes it.
  5. hilt-check gains a rule that flags the deprecated spelling and names the replacement, in the pattern of hilt/retired-names, so the finding reaches the developer's CI before it reaches a station log.

The developer sees the warning in the self-tests of their own suite (pytest surfaces DeprecationWarning by default) and in hilt-check output; hilt run routes Python warnings through the run log so the station's console carries the notice as well.

A removal at the next MAJOR deletes the code and the rule, moves the table row to the changelog's Removed list, and stops there: a removed name is not reused for something else within the following MAJOR line.

The changelog¶

CHANGELOG.md at the repository root follows Keep a Changelog: an Unreleased section at the top, one section per release below it, entries grouped under Added, Changed, Deprecated, Removed, Fixed, and Security.

Every MR that changes a public name, a documented contract, a record format, or a hilt-check rule adds its line to Unreleased in the same MR. A release renames Unreleased to the version and date and opens a fresh Unreleased above it. The changelog is the announcement; the GitLab issue is the ruling behind it.

Changing the surface¶

A change to the public surface is a change to a promise, and the workflow in STANDARDS.md section 7 applies: it is raised as an issue for Ty's sign-off before its MR opens, stating how the change helps the developer help the Floor Technician. The MR then updates hilt.__all__, the reference table below, the section that documents the name, and CHANGELOG.md together. The public-surface self-test refuses an MR that updates one without the others.

ArpResolutionFailure ¶

ArpResolutionFailure(message: str, *, mac: str, host: str)

Bases: HiltError

The resolver could not map a MAC address to an IP.

This is not a TestFailure. That is deliberate:

  • Uncaught in a test method or configure, the child boundary classifies it as a developer bug. The suite did not model this failure mode at all.
  • Caught and re-raised as TestFailure, the author acknowledged the mode and chose the verdict shape: the device did not appear on the network.

Catching this does not tell you why the ARP entry is missing — dead NIC, unplugged cable, hungry switch, DHCP failure, or a gateway that has not seen traffic from the target yet. No amount of code can distinguish those. Hardware versus infrastructure is the human triager's call from logs, survey artifacts, and the bench. Do not write code that pretends to know.

If this extended TestFailure, an uncaught miss would land in Fail and look like a modeled hardware verdict, hiding that the author never handled the mode.

Record the MAC that could not be resolved and the host that was asked.

Name Type Description Default
message str

What failed, in the FT's language.

 required
mac str

The normalised MAC that was missing from the table.

 required
host str

Routing label of the host whose ARP table was read ("local", "via 10.0.0.1", …).

 required

ArpResolver ¶

ArpResolver(
    *,
    mac: str,
    ping_count: int = 1,
    exec_fn: ExecFn | None = None,
    logger: ScopedLogger | None = None,
    cache_key: str | None = None
)

Resolve a MAC address to an IP through the node's current exec route.

resolve() returns a plain dict suitable for spreading into configure()'s return value. ping(utils) is a gated reachability claim. reacquire(utils) forces a fresh table read after a reboot, flash, or DHCP churn and returns the new IP; the resolver remembers it, so a later ping(utils) dials the address it last resolved. Ctx is read-only after configure(), so the address that moves lives in the resolver, and a test that wants it on the record carries it as evidence: PASS({"ip": ip}).

Raises:

Type Description
ArpResolutionFailure

The MAC is missing from the table, or /proc/net/arp is unreadable. This is not a TestFailure. Uncaught it is a developer bug — the suite did not model the failure mode. Catch it and re-raise as TestFailure to make "the device did not appear on the network" a verdict. Hardware versus infrastructure remains the triager's call.
RuntimeError

resolve() was called on an instance that was not created through utils.get_arp_resolver().
ValueError

mac does not contain 12 hex digits, or ping_count < 1.

Bind a MAC. Authors go through utils.get_arp_resolver(), not this.

resolve async ¶

resolve() -> dict[str, str]

Refresh a stale cache and return {"ip": ...} for this MAC.

Zero-arg: uses the exec and cache key get_arp_resolver bound. Raises if this instance was constructed without that scope.

reacquire async ¶

reacquire(utils: TestUtils) -> str

Force a fresh ARP read and return the new IP.

Call from a test method after anything that may have changed the IP. The cache key stays the resolver's — that is the host whose table holds this MAC — while the command runs through the child's utils.exec. The resolver's shared table now holds the new address, so ping(utils) on any resolver for this MAC dials it; carry it as evidence on the verdict if the Floor Technician should see it.

ping async ¶

ping(utils: TestUtils) -> Verdict

Reachability claim against this MAC's last resolved IP.

The address is read from the resolver's table for this MAC, which resolve() and reacquire() both refresh, and falls back to utils.ctx["ip"] for a context that was seeded without a resolve. Uses the child's exec and logger. Packet loss and a missing stats line are TestFailure. Duplicate replies (received > transmitted) still count as success — the host answered. A missing IP (resolve never ran) is ArpResolutionFailure.

CoapCode ¶

Dotted CoAP response codes, the form a record can carry.

A CoAP DeviceResponse.status is one of these strings ("2.05"), never the wire integer class << 5 | detail. HTTP status stays an int. Compare with response.status == CoapCode.CONTENT and put response.status on the evidence as-is: it is already the text a reader sees. from_wire is how the transport, and a claim that still holds a code byte, spells that integer.

DeviceApi ¶

DeviceRequest dataclass ¶

DeviceRequest(
    method: DeviceMethod,
    path: str,
    payload: bytes | None = None,
    headers: Mapping[str, str] = MappingProxyType({}),
    retries: int = 0,
    retry_delay: float = 0.05,
    retry_non_idempotent: bool = False,
    timeout: float | None = None,
    evidence_headers: frozenset[str] = frozenset(),
    *,
    json: InitVar[Any] = _NO_JSON
)

One resource operation: method, path, optional payload, optional headers.

Path is relative to the handle's base URL. Use payload for raw bytes or keyword-only json for a JSON value, including None (JSON null). JSON is encoded once as UTF-8 and adds Content-Type: application/json unless a content type was supplied. Supplying both bodies raises ValueError; unserializable or non-finite JSON is refused at construction. retries counts extra application-level attempts after the first; the default is zero. Attempt logs withhold every header value unless the name is in evidence_headers.

DeviceResponse dataclass ¶

DeviceResponse(
    status: int | str,
    body: bytes,
    headers: Mapping[str, str] = MappingProxyType({}),
)

The bytes and status a transfer actually returned.

HTTP 4xx/5xx and CoAP 4.xx/5.xx are fields here, not exceptions. An HTTP status is the integer. A CoAP status is the dotted code ("2.05", :class:CoapCode). headers carries HTTP headers or CoAP options as strings. body is the payload bytes. Parsing is opt-in through json() or parse(response_type=...); a parsing error never changes the transfer's status or raw bytes.

json ¶

json() -> Any

Decode the body as JSON, independent of status and content type.

Raises json.JSONDecodeError for malformed JSON and UnicodeDecodeError for invalid encoding. No fallback value is invented.

parse ¶

parse(
    response_type: Literal["json", "yaml"] = "json",
) -> Any

Decode the body in the explicitly selected format; default is JSON.

YAML uses yaml.safe_load and requires the hilt-core[yaml] extra. Parser errors propagate unchanged; an unknown response_type raises ValueError. Parsing never sends a request or changes the response.

ExecResult dataclass ¶

ExecResult(
    stdout: str,
    stderr: str,
    exit_code: int,
    truncated: bool = False,
    captured_bytes: int = 0,
)

What a host command produced.

A non-zero exit_code is evidence, not an exception. -1 means the process was killed by a signal, or was aborted before an exit status existed. truncated means stdout+stderr together hit the output budget; captured_bytes is how much was kept. Existing callers that omit both still construct a result.

settled classmethod ¶

settled(
    stdout: str | bytes | None,
    stderr: str | bytes | None,
    exit_status: int | None,
    *,
    truncated: bool = False,
    captured_bytes: int | None = None
) -> ExecResult

Settle raw transport output into a result.

Output arrives as whatever the transport produced — bytes (decoded UTF-8 with replacement), str, or nothing (empty). An exit_status of None or below zero means no real status exists — signal kill, or abort before an exit status — and settles as -1. Every transport builds its results here, so the -1 contract cannot drift between them. Truncation is evidence, not an exception: the marker and byte count ride on the same result.

HiltError ¶

Bases: Exception

Root of the framework's own exception taxonomy.

Catching this catches everything hilt raises deliberately and nothing a suite author raises by accident.

A failure recorded at the child boundary is bound to the run's redactions (issue #154): from then on str(), repr(), and to_json() mask every secret the suite declared through redact_ctx, so a TestFailure that was handed a session credential as its received value renders it as <REDACTED> on every surface. Every to_json in the taxonomy is wrapped at class creation, so a subclass need not know the masking exists.

Measurement dataclass ¶

Measurement(
    name: str,
    value: int | float | None,
    unit: str | None,
    limits: Limits | None,
    in_limits: bool | None,
    timestamp: datetime,
)

One utils.measure call, exactly as recorded.

Frozen because the record is sealed with the node: a consumer keys a time series on name together with the node path, so a value that could change after the call would corrupt the series it belongs to. in_limits is None when the reading was recorded without a window, True or False otherwise; it is a recorded fact, and the verdict is decided elsewhere.

A reading that was not taken has value=None. It is never inside its window, so in_limits is False when limits were given: a gate written on the window fails the claim however it is spelled, and the claim decides what a missing reading means. Without limits it is None, as for any trend reading.

The developer's label for the reading, or None for a dimensionless count. Never validated, never converted.
limits Limits | None

The inclusive (low, high) window, or None when none was given.
in_limits bool | None

Whether value sits inside limits; False for a reading not taken against a window; None without limits.

When the reading was recorded, timezone-aware UTC.

Phase ¶

Bases: StrEnum

The six survey dispatch points of one node lifecycle, in the order they occur.

The values are the artifact-name prefixes the Evidence Contract already publishes (pre-configure-1), so naming a phase in code names it in the run directory. Members order by declaration, not by string: Phase.PRE_TEST < Phase.POST_TEST holds. Order is not reach. RunEnv ¶

RunEnv(values: Mapping[str, str])

Bases: Mapping[str, str]

The run environment: a read-only mapping with readers that Fail the run.

Contract
  • It is the filtered, immutable snapshot TestUtils.env publishes on every RunResult. get, in, [], and iteration behave as on any mapping.
  • text(name) trims the value and treats blank as unset. A bench script that exports TARGET_PASSWORD="" means "no password", not "the empty password".
  • require(name) raises TestFailure naming the variable to set. Called from configure, that is the "did not reach a testable state" verdict: the run Fails before any claim runs, and the message is the operator's instruction.
  • port(name, default=22) parses an integer in 1-65535 and raises TestFailure for anything else, so a bench typo is reported as the variable rather than surfacing later as a transport error.
  • int(name, default=) and float(name, default=) do the same for a number. Unset or blank uses default when one was passed, and otherwise Fails naming the variable. A value that is not a base-10 integer, or not a finite float, Fails naming the variable and the value.

Record one parametric reading on this node, beside the verdict.

A limit is evidence, never a verdict: the reading is recorded with in_limits decided and nothing about the node's state changes. When the window is a pass criterion, gate on the returned record in plain sight so the verdict's predicate is visible to the reader and to hilt/gated-pass::

rail = utils.measure("output_voltage_v", volts, unit="V", limits=(4.75, 5.25))
if rail.in_limits:
    return PASS({"output_voltage_v": volts})
raise TestFailure("rail outside window", "4.75-5.25 V", f"{volts} V")

Verdict ¶

The value that means "this node passed", with or without evidence.

Contract
  • Exactly one bare instance exists per interpreter. Verdict() returns it; copying, deep-copying, and unpickling all return it. It is the value bound to PASS.
  • PASS(evidence) mints a verdict that carries a detached copy of evidence. It is a distinct object, so identity with PASS is never the check: the child boundary asks isinstance(result, Verdict).
  • evidence is read-only. The boundary copies it into run_data after checking every entry; a carrying verdict cannot be edited after it is returned.
  • repr() is the bare word PASS, or PASS({...}) for a carrying verdict, so logs and artifacts read as the FT expects rather than showing an address.

The type parameter is the evidence shape. A method annotated -> Verdict[MyEvidence] with a TypedDict has its PASS({...}) payload checked against that shape by pyright; the bare -> Verdict accepts any mapping.

evidence ¶

@evidence: the readings a test method promises to carry on PASS.

A test method is a function from utils.ctx to a verdict. The decorator is the method's return signature: it names the keys a pass must carry, beside the code that keeps the promise. It annotates and registers nothing; build_suite still names and binds the method. The declaration is fixed at class definition and never computed at run time: pass criteria that vary by SKU or fixture are a leaf argument or a different leaf, decided before build_suite runs (issue #118).

The child boundary holds PASS to the declaration: a declared key the payload does not carry is a ContractViolation naming the leaf and the key. Extra keys are allowed; the declaration is a floor. TestFailure is not held to it, since a failure may fire before every reading was taken. An undecorated method may still return PASS(payload); the payload is recorded unchecked.

Two spellings::

@evidence("output_voltage_v")
async def _check_voltage(self, utils: TestUtils) -> Verdict: ...

class VoltageEvidence(TypedDict):
    output_voltage_v: float

@evidence(VoltageEvidence)
async def _check_voltage(self, utils: TestUtils) -> Verdict[VoltageEvidence]: ...

The TypedDict form declares its required keys at run time and lets pyright check the PASS({...}) payload against the shape at write time.
